# 技能资料与静态资源

本目录向 TestPilot 的规划与执行 Agent 提供指导和参考资料。Skill 是以 `SKILL.md` 为入口的一组指导文本及附件；静态资源可以是独立的文字或图片。规划根据资料设计语义任务，执行依据真实观察选择工具操作。

应用直接读取本地资料，也支持读取 MCP 服务公开的资源。应用使用流程见[项目 README](../README.md)，更改本地资料根目录见[参数说明](../README.md#规划执行参数与目录)。

## 添加本地 Skill

默认目录分工如下：

| 目录 | 用途 |
|---|---|
| `base/` | 随应用维护的基础 Skill |
| `external/` | 用户添加的外部 Skill，内容由 Git 忽略 |

在相应目录下创建一个包。以下为布局示例，按实际需要添加附件：

```text
external/
└── display-check/
    ├── SKILL.md
    ├── references/
    │   └── display-rules.md
    └── assets/
        └── reference.png
```

`SKILL.md` 使用 UTF-8，开头通过 YAML frontmatter 提供名称和用途。例如：

```markdown
---
name: display-check
description: 检查电视页面文字的完整性、可读性和遮挡情况时使用
---

# 页面显示检查

根据当前任务的成功标准，获取实际画面后检查目标文字。
参考 [显示检查规则](references/display-rules.md)；
需要理解示例时查看 [参考图](assets/reference.png)。

参考图只说明检查方式。结论应依据待测电视的实际观察。
```

描述应说明何时使用，正文写清操作方法、观察要求及附件用途。资料不能更改已确认任务的目标、成功标准或系统规则。附件中的脚本不会自动执行，链接也不会自动展开。

包的范围是 `SKILL.md` 所在目录及其全部子目录。可以在子目录再放置 `SKILL.md` 形成子 Skill；直接放在资料根目录中的文字和图片也可以作为普通资源读取。

## 发现与按需读取

应用启动和手动刷新时全量发现资源，供规划页中栏“MCP”“本地资源”卡片和右栏“资源与 MCP”卡片预览；规划与执行选择分别维护。规划及运行准备只重新发现已选 MCP 服务，展开这些服务公开且支持读取的 Skill manifest，同时完整扫描本地目录元数据以识别全部顶层包边界。校验已选栏目的目录条目及能力定义与预览一致后，分别在计划背景或运行环境保存本轮发现的完整目录及勾选状态，包含已选 MCP 服务及全部本地资源，包括未选本地包；未选 MCP 的缓存目录仅保留在预览中。Agent 初始只获得自身已选栏目中没有上级 Skill 的顶层摘要；具体正文、子 Skill 和附件在需要时读取。

MCP 按服务整栏选择；本地按顶层 Skill 包选择，包内包含子 Skill 和附件。“其他本地资源”是配置根目录中不属于任何已发现顶层包的资料，始终排除未选包。首次预览全部勾选；刷新保留原有选择，新栏目不勾选。全部取消后内置读取工具仍存在，但资源列表为空，读取任何外部资料均表现为不存在。

资源通过来源 `source_id` 和完整地址 URI 标识：

| 来源 | 标识和地址 |
|---|---|
| 本地 | `source_id = "local"`，使用目录中给出的 `file:` URI |
| MCP | `source_id = "mcp:<服务名>"`，服务名来自应用连接文件，使用服务公开的 URI |

Agent 使用以下工具：

| 工具 | 作用与参数 |
|---|---|
| `list_resources` | 列出本次已选栏目公开的资源和地址模板；可按 `source_id` 筛选，也可同时提供 `source_id`、`skill_uri` 限定包范围 |
| `load_skill` | 按 `source_id` 和入口 `uri` 加载一个 Skill，仅读取该 `SKILL.md` |
| `read_resource` | 按 `source_id`、`uri` 读取文字或图片；读取相对引用时另提供 `base_uri` |

正文中的相对链接保持原样。读取 `references/display-rules.md` 时，应把当前 `SKILL.md` 的完整 URI 作为 `base_uri`；使用目录地址作为基础时，末尾必须带 `/`。优先复制目录或读取结果给出的 URI，避免根据文件名猜测位置。

按父包列资源时，子 Skill 入口与附件都作为普通资源返回；以子入口筛选可限定到子包。加载子 Skill 不连带读取父级、其他子包或附件。

本地读取限制在已配置的资料根目录内。已知不支持的二进制 MIME 类型会直接返回说明；当前可读取文字和图片。规划参考图片仅用于本轮，不代表电视当前状态，也不创建执行附件。执行图片的上下文保留与历史保存规则见[参数说明](../README.md#规划执行参数与目录)及[历史与报告](../README.md#历史与报告)。

成功加载的 Skill 正文只为当前一次规划或任务执行保留；同一入口再次加载成功时采用最新内容。进入下一次规划或任务执行需要按需重新加载，包括 Goal 回跳后的重入。资料调用使用各自独立的规划或执行轮次、超时和纠错额度。规划可参考外部工具说明，但只能调用资源读取及最终计划提交工具；资料不能扩展其操作权限。

## 通过 MCP 提供资料

MCP 服务可以公开资源列表、资源地址模板和读取能力。服务连接方式见[外部工具连接](../README.md#外部工具连接)，可控资源场景的编写见 [Fake MCP](../mcp_servers/fake_mcp/README.md#提供静态资源)。

MCP 资源仅在使用 `skill` scheme 且文件名为 `SKILL.md` 时识别为 Skill，例如 `skill://display-check/SKILL.md`。其他 URI 仍可作为普通资源列出和读取。包范围以同一来源、相同 scheme 和 authority 下的父路径确定，与服务端物理目录无关。

服务提供顶层 Skill 的名称和摘要时优先使用；缺少时读取入口中的信息补充。Agent 不会预先加载所有资料正文。

公开附件通过资源列表或服务明确公开的清单发现。应用在发现阶段展开 FastMCP 公开且支持读取的 Skill manifest，查询列表不再临时展开。普通地址模板本身不表示可以浏览服务端文件系统，也不保证可以枚举所有可读 URI。

目录用于发现，读取按栏目授权判断。同一已选 MCP 服务内，即使正文引用的资料没有被目录或 manifest 列出，也可以尝试读取；本地在本次已选包或其他本地资源范围内同理。跨未选栏目引用表现为资源不存在，不因物理文件存在而放行。例如只选其他本地资源时，其中的文档也不能读取未选 Skill 包的附件。相对地址和路径别名均按规范化后的真实路径判断，本地读取仍受配置根目录限制。

## 更新与排查

规划及运行准备会重新发现资源，校验已选栏目的目录与预览一致后，固定本次资源目录和栏目边界。过程中的 `list_resources` 查询和目录快照使用各自准备得到的目录；查询仅返回已选栏目的公开资源条目，不重新扫描文件或展开清单。修改配置或刷新预览不改变已有工作的客户端批次和授权范围。正文在调用时读取，因此修改文件可能影响当前工作后续的读取；目录一致性校验不比较正文。需要可重复结果时，应在工作期间保持资料不变；新增公开目录项通过刷新预览及新规划或运行发现。

目录快照保存完整发现元数据和每个栏目的勾选状态，包括未选栏目，供计划或运行追溯。执行已读取内容保存在实际运行消息中，规划正文和图片只用于本轮，不能把目录快照当作全部正文的归档。

| 现象 | 检查方向 |
|---|---|
| 新 Skill 没出现在初始摘要 | 确认入口名为 `SKILL.md`、目录在配置根目录内；嵌套 Skill 通过父包按需发现；新增后创建新运行 |
| 相对链接读取失败 | 核对来源、`base_uri` 是否为完整地址，以及目录基础地址是否以 `/` 结尾 |
| MCP 入口只作为普通资源 | 检查 URI 是否采用 `skill` scheme，文件名是否符合入口规则 |
| 资源存在但列表无法展开 | 检查服务是否公开了资源条目或可读清单；只有模板不保证可枚举 |
| 文件类型无法读取 | 提供可读取的文字或图片版本；其他二进制文件保留目录信息 |
