# TestPilot：Android TV 主观测试 Agent

TestPilot 面向内部 Android TV 测试人员。输入自然语言测试用例，检查并确认生成的计划后，Agent 根据实际观察选择操作、验证要求，最终提供可追溯的运行结果和报告。

典型流程：**录入用例 → 生成并确认计划 → 执行测试 → 复核运行记录 → 导出报告**。

应用提供用例管理、计划修订、实时执行与取消、历史检索和统计。电视操作、截图等能力由独立的 MCP 服务提供；MCP 是应用连接外部工具的协议。当前采用单运行串行模式，同一时刻只接受一次运行的准备与执行。

## 快速开始

首次使用按以下顺序准备；已有环境可以从尚未完成的步骤继续：

1. 按[安装应用](user_scripts/README.md#安装应用)准备 Windows、Python 和 Node.js 环境，并安装应用依赖。
2. 按下方[配置应用](#配置应用)准备本地配置，填入真实模型服务信息。
3. 使用电视时，按 [ATV MCP 文档](mcp_servers/atv_mcp/README.md#准备环境与设备)准备服务依赖和设备配置；需要可控协议回放时使用 [Fake MCP](mcp_servers/fake_mcp/README.md)。在[外部工具连接](#外部工具连接)中只启用此次测试需要的服务。
4. 按[启动与停止](user_scripts/README.md#启动与停止)启动应用、打开页面，然后完成下面的首次测试。

安装与诊断命令由[用户脚本文档](user_scripts/README.md)统一维护。Skill 和参考资料的接入见[技能资料与静态资源](skills/README.md)。

## 完成第一次测试

### 1. 创建用例

在“规划”页选择“新建用例”，填写名称和自然语言正文。例如：

> 名称：关于页面版本号显示
>
> 正文：进入电视设置的关于页面，检查固件版本号。要求版本号非空、文字完整可辨，且没有被截断或遮挡。

名称和正文都必须包含非空白内容，名称最多 200 个字符。正文应写清目标、适用前提和可观察的预期，主观描述尽量具体。

### 2. 生成并检查计划

首次点击“生成计划”前，可以补充本次规划的要求。等待进度弹窗显示保存完成后，检查准备步骤、前置假设和每个任务的目标、成功标准。

规划期间仅限制当前用例详情和任务区域，左侧用例列表及主导航保持可用。可以切换用例、进入其他页面，也可以规划或运行其他用例；运行仍遵守全局单运行限制。切回后重新加载详情，并恢复本次应用会话中仍未结束的规划进度和日志。

规划成功后自动关闭进度弹窗并清空本轮额外输入；失败后保留日志与输入，关闭弹窗即可修改输入重试。刷新浏览器、关闭页面或应用后不恢复临时进度、日志和输入，也不自动重新提交；已保存的计划仍可正常读取。

| 任务类型 | 含义 |
|---|---|
| Act：达成目标 | 根据当前状态选择操作，达到指定业务状态 |
| Judge：验证要求 | 实际验证待测行为与成功标准，可以为验证准备条件和触发交互 |
| Goal：判断结束条件 | 判断重复工作是否结束；条件未满足时回到预先指定的前序任务 |

计划表达语义目标，执行时再决定具体动作。Judge 的交互必须服务于待测行为，不能绕过它或改变成功标准。

需要调整时选择“编辑计划”，修改后“保存新版本”。准备步骤是给用户的提示；需要让 Agent 执行时，可将其转为任务，补全目标和成功标准后保存。Goal 的回跳目标必须在同一计划中且位于它之前；删除或重排任务使目标失效时，按页面提示重新选择。

### 3. 确认并执行

完成准备，检查最新计划，勾选确认前置假设、任务目标和成功标准，然后启动。只有最新的已保存计划可以启动；未保存的修改必须先保存或放弃。

中栏下方并排的“MCP”和“本地资源”卡片用于选择本轮规划的参考范围，右栏“资源与 MCP”卡片独立选择本次运行的能力。两边弹窗均按 MCP 服务、本地顶层 Skill 包和其他本地资源分栏，栏目内工具和资料整体启用。首次取得预览默认全选，规划卡片的全选与取消只影响自身栏目；全部取消仍保留各自的内置工具。当前选择只保留在本页，重进页面或切换用例后重新初始化；提交后的实际目录和选择分别保存在计划背景或运行环境中。历史入口会带当前用例的筛选条件。

应用启动和手动刷新时全量发现能力，形成目录预览。启动发现失败可以重试，用例、历史和设置仍可访问，取得有效预览前不能提交规划或启动。规划和执行共用同一份目录预览，勾选分别保留；首次取得有效目录时各自全选。目录读取或主动刷新成功后两处同时展示新内容，各自保留仍存在栏目的勾选、移除消失栏目，新栏目不勾选，全部取消后保持为空。

规划和启动前只重新发现已选 MCP 服务，并完整扫描本地目录元数据以确定全部 Skill 包边界；未选 MCP 服务不建立连接，其不可用不影响本次准备。所选栏目的目录条目或能力定义变化时，后端更新预览缓存并拒绝该次操作，提示用户检查选择后重试。前端自动读取已更新的缓存，同步两处目录，无需再次全量发现。读取失败可重试读取；读取成功且其他业务条件满足后按钮恢复可用，用户自行检查卡片并再次提交。规划失败弹窗仍需关闭，本轮额外输入保留；系统不会自动重新规划或启动。每次提交都使用各自的勾选和共享目录中的当前指纹，未选栏目的变化不阻止操作，准备时新增但未提交选择的栏目不会自动启用。

规划 Agent 可多轮加载 Skill、列出和读取参考文字或图片，再通过 `finish_plan` 提交完整计划。所选 MCP 工具说明用于理解执行能力，规划不能调用业务工具操作或观察电视。参考资料不能代表电视当前状态；计划继续以自然语言描述任务方向、边界及可观察成功标准。进度显示实际决策轮次和工具结果，成功保存后才显示完成。读取正文、图片和临时日志不生成运行或执行附件。

进入“执行”页后，可以查看任务队列、最新图片、运行资源和消息时间线。轮次表示决策预算使用量，观察、操作、纠错、读取资料和提交结论都会消耗轮次，不能据此推算完成百分比。

需要终止时点击“终止”，等待服务端确认结果。具体取消和结果含义见[执行与结果](#执行与结果)。

### 4. 复核与导出

运行结束后选择“查看执行记录”，检查实际观察、各次任务执行的判断说明及最终结论。查看和下载方式见[历史与报告](#历史与报告)。

## 日常管理

- **修改用例**：“编辑用例”同时保存名称和正文，保留用例编号。已有计划和运行保持原样；保存后需检查计划并重新确认，重新规划会读取最新用例内容。
- **重新规划**：填写本轮调整要求，以最新已保存计划为基础生成新版本。存在未保存修改时，先保存或放弃。规划失败保留既有计划；请求结果未确认时，先检查最新版本，再决定是否重试。
- **查看版本**：右侧“任务序列”可切换版本。历史版本只读；修订和重新规划均创建新版本，不覆盖旧版本。新版本不改变已经开始的运行。
- **归档用例**：用例卡片的收纳图标用于归档。确认后从规划页移除，历史运行和报告仍保留。归档是单向操作，归档用例不能继续规划或重跑。

规划先固定本轮输入，准备期间不能保存该用例；准备完成后，其他窗口提交的用例修改只用于后续规划，不改变本轮输入。规划全程不能人工修订计划、归档或启动该用例的运行。运行准备及记录创建期间不能规划或修订同一用例，但允许保存用例；记录创建成功后可以另行编辑用例、规划或修订计划，已有运行仍依据启动时确认的版本执行。归档与同一用例的其他处理互斥，整个运行工作结束前不能归档。

## 执行与结果

每次启动都会创建独立运行，固定使用已确认的计划、模型和工具目录。回跳重入同一任务时会产生新的任务执行记录，先前记录继续保留。

任务通过后继续下一项；不同类型未通过时的处理如下：

| 情况 | 后续处理 |
|---|---|
| Act 失败 | 停止，跳过当前任务之后的队列后缀 |
| Judge 失败 | 保留失败并继续后续任务 |
| Goal 条件未满足 | 在该 Goal 的累计失败额度内回到已确认目标；额度耗尽后停止并跳过后缀 |
| 任意任务阻塞 | 停止并跳过后缀 |
| 响应人工取消 | 停止，不为尚未开始的后续任务新增执行或跳过记录 |

后续任务需要前序观察时，应在计划中明确采集内容、保留要求和使用来源。任务结果中的“跨任务记忆”可保留实际观察值、单位和图片引用，供同一运行后续任务使用；新运行从空记忆开始。

整个运行的最终结论由程序汇总，含义如下：

| 结论 | 含义 |
|---|---|
| PASS：通过 | 正常结束，没有导致失败或阻塞的情况 |
| FAIL：失败 | 存在 Act 或 Judge 失败，且没有优先级更高的阻塞或取消情况 |
| BLOCKED：阻塞 | 无法完成判断或继续执行，例如观察不足、预算耗尽、外部调用或存储故障 |
| CANCELLED：取消 | 已在安全边界响应人工取消，且没有未处理的执行故障 |

聚合时，未处理执行故障优先于取消，其次是任务阻塞或 Goal 失败额度耗尽，再考虑 Act/Judge 失败。Goal 历史上的“条件未满足”和跳过记录本身不独立决定 FAIL。

取消请求会等待当前模型或工具调用完成或达到超时，再阻止下一次调用；已经收到的图片仍需保存。页面显示“取消请求已提交”时，运行尚未必结束，应等待已保存终态。异常退出后，应用重启会将遗留的未结束运行标记为进程中断导致的 BLOCKED；再次执行需重新确认计划并创建新运行。

模型给出的任务摘要应说明观察、判断依据及其与成功标准的关系。文字和图片都可以作为观察，参考图和历史图保留各自来源与时点。截图数量不决定通过或失败；应复核实际记录是否足以支持结论。

## 配置应用

### 本地配置文件

首次配置时，在仓库根目录执行；已有本地文件时直接编辑，保留原配置：

```powershell
Copy-Item config.example.toml config.toml
```

- `config.toml`：应用参数、模型列表与选择、模型密钥、执行预算，以及数据和资料位置；不进入 Git 跟踪。
- `config.example.toml`：完整填写样板，仅供人参考和复制，不参与运行、测试或工具的配置加载。
- `mcp_servers/mcp.json`：默认外部工具连接文件，格式见[外部工具连接](#外部工具连接)。

应用默认读取仓库根目录的 `config.toml`。如需选择另一份完整配置，在启动终端设置唯一的宿主配置环境变量：

```powershell
$env:TEST_AGENT_CONFIG_PATH = "D:/agent-config/config.toml"
```

该变量只选择文件，不覆盖单个参数。所选文件是唯一配置来源；应用不读取 `.env`，也不使用样板补齐参数。必要参数必须在实际文件中填写，缺失文件、缺失必要项或未知字段会阻止启动。

配置文件路径及文件内部的相对路径都从仓库根目录解析。后端启动时读取所选文件一次，并固定后续设置保存的目标文件；运行期间改变配置文件选择环境变量不会改变该保存目标。文件中不能设置 `config_path`，来源文件由启动时的选择确定。运行期间通过“设置”页保存，模型、规划与执行参数对新工作生效，目录发现超时对下次发现生效。运行期间手工修改文件不会自动载入，后续页面保存会覆盖文件中的修改。

### 设置页与生效时机

“设置”页按用途展示参数及中文说明，顶部“保存设置”整体提交当前草稿。前后端独立校验，不合法时显示字段或分组原因。模型列表支持新增、修改和删除，规划与执行模型均须显式选择；列表位置不决定选择。

模型及各自完整的规划或执行参数在准备阶段固定，保存新设置不改变已开始的工作。独立的能力目录发现超时在每次发现入口读取最新值，进行中的发现保留原时限；此项不属于启动参数，也不进入规划或执行快照。设置保存与所有规划准备、运行准备互斥，冲突时稍后重试；多个窗口基于旧版本保存会被拒绝，需重新加载后编辑。普通保存失败保留草稿，刷新或离开设置页不保留未保存内容。

启动参数标注为重启生效；保存的新值如实显示在页面。本进程内只要成功修改过启动参数，顶部就持续提示重启，即使改回原值也保留提示。实际消费者继续使用启动时取得的值。

已有模型令牌不会返回浏览器，空输入显示是否已配置。留空保存保留已有令牌，输入新值后保存会替换；眼睛按钮只显示本次输入，成功保存清空令牌草稿。新真实模型必须填写令牌。本地 TOML 继续以明文保存令牌。

每次保存覆盖启动时选中的文件，不保留注释或原排版；可选空值省略，路径按现有根目录规则规范化。保存失败不更新内存配置或版本。响应超时或中断时，先用“重新加载”确认结果，再决定是否重试。

### 模型服务

真实使用需要兼容 OpenAI Chat Completions 的模型服务。规划与执行模型均需支持工具调用，以及实际使用的文字和图片输入。Act、Judge 和 Goal 共用一个执行模型。

样板中的首个 profile 是 `scripted` 测试模型，没有显式执行场景时会阻塞，不能用它验证真实电视。在实际配置中保留应用及执行参数，将模型列表替换为以下完整 profile，并将占位值和容量改为服务实际支持的值：

```toml
[[llm.profiles]]
id = "tv-model"
mode = "real"
base_url = "https://provider.example/v1"
api_key = "replace-with-your-key"
model = "replace-with-your-model"
temperature = 0
timeout_seconds = 60
context_window_tokens = 32768
max_output_tokens = 2048
characters_per_token = 1.5
tokens_per_image = 1024
context_safety_margin_tokens = 1024
```

`base_url` 填写服务的 OpenAI 兼容 API 基地址。上例仅说明文件格式，不表示任意服务都支持该容量。

多模型时添加多个 `[[llm.profiles]]`，每份配置使用唯一 `id`。在 `[llm]` 中通过必填的 `planning_model_id` 和 `execution_model_id` 选择对应 ID；两个选择都必须存在。使用上面的 `tv-model` 示例时，将两个选择也设为 `tv-model`。省略可选项时不要填写空字符串。

每份 profile 支持的参数如下：

| 参数 | 样板初始值或填写要求 |
|---|---|
| `id` | 必填，唯一、非空 |
| `mode` | 必填，样板为 `scripted`；真实服务填写 `real` |
| `base_url`、`api_key` | `real` 模式必填 |
| `model` | 必填，填写真实模型名称；样板测试模型为 `deterministic` |
| `temperature` | `0` |
| `timeout_seconds` | `60` 秒，必须大于零 |
| `context_window_tokens` | `32768`，至少 `2048` |
| `max_output_tokens` | `2048`，必须大于零 |
| `characters_per_token` | `1.5`，文字容量估算，必须大于零 |
| `tokens_per_image` | `1024`，单图容量估算，必须大于零 |
| `context_safety_margin_tokens` | `1024`，安全余量，可为零 |

除模拟模型可以省略服务地址与密钥外，表中模型参数都需显式填写，Python 不提供固定参数默认值。输出预留与安全余量之和必须小于上下文总容量。必需的任务、观察或技能资料装不下时，运行会因容量不足阻塞。格式错误、空 profile 列表、重复 ID、未知字段或无效选择会阻止启动。

模型适配性可用[独立模型检测](user_scripts/README.md#检查模型服务)排查；该检测支持的协议范围与应用实际使用的协议分别定义。

### 系统指导文本

需要调整 Agent 的规划或执行指导时，编辑 [backend/app/resources/prompts/](backend/app/resources/prompts/) 中的文本文件，然后重启后端。`planning.txt` 用于规划，`act.txt`、`judge.txt`、`goal.txt` 分别用于对应任务。

执行优先使用任务类型专用文件；文件缺失时使用可选的 `execution.txt`，两者不拼接。显式空文件会覆盖通用指导，最终都缺失时采用空指导。计划和运行记录实际选用文本的内容指纹，供复核版本。

### 外部工具连接

应用通过标准输入输出（stdio）启动独立 MCP 进程。应用配置根字段 `mcp_config_path` 指定连接文件，样板使用 [mcp_servers/mcp.json](mcp_servers/mcp.json)。

连接文件的顶层字段为 `mcpServers`，其下每个非空服务名对应一份配置：

| 字段 | 用途 |
|---|---|
| `command` | 必填，直接执行的程序，不经 shell |
| `args` | 命令参数列表，默认空列表 |
| `cwd` | 工作目录；省略时使用连接文件所在目录，相对路径也以该目录为基准 |
| `env` | 显式环境变量，应用于协议客户端继承的启动环境 |
| `transport` | 当前仅支持 `stdio`，可省略 |

`command: "python"` 使用启动环境 PATH 中的解释器；服务有独立环境时填写它的解释器绝对路径。

仓库默认连接 ATV 服务，其设备设置及启动参数由 [ATV MCP 文档](mcp_servers/atv_mcp/README.md)维护。回放服务的参数和场景格式由 [Fake MCP 文档](mcp_servers/fake_mcp/README.md)维护。

连接配置在应用启动发现、用户刷新能力目录、每次规划准备及运行准备时完整读取和校验。全量发现整体更新预览；定向准备按已选 MCP 服务整栏更新缓存，包括条目删除、空目录和服务移除，未选 MCP 目录沿用缓存。本地目录每次发现都重新扫描，普通预览读取不连接服务。启动发现失败不会阻止应用启动，定向准备要求已有有效预览。各次规划和运行固定本次客户端批次、本轮发现的完整目录及栏目选择，包含已选 MCP 服务、全部本地资源和内置能力；未选本地包保留在快照中以确定授权边界，未选 MCP 的缓存目录仅用于预览。后续刷新不改变已有快照。

同一轮发现复用服务连接，覆盖工具目录、资源目录、Skill 清单展开和摘要补齐，结束后统一释放。预览和规划只获取外部工具定义；执行准备在所选栏目校验通过后装配可执行工具。每次资源或业务工具调用仍独立建立和结束会话，stdio 进程可能重新启动；服务需自行保持跨调用所需的业务连续性。规划准备完成后的模型决策、运行中的目录查询及历史查看不重新发现服务。新增文件按准备时冻结的栏目边界判断，不在运行中重新扫描 Skill 包。

### 规划、执行参数与目录

以下参数在实际 TOML 中显式填写，完整样板见 [config.example.toml](config.example.toml)。表中的数值是建议初始值，不是缺项时自动补入的值。

| TOML 参数 | 样板初始值与作用 |
|---|---|
| `app_name`、`app_version` | `Android TV Test Agent`、`0.1.0`，应用名称和记录的版本 |
| `mcp_config_path` | `./mcp_servers/mcp.json`，外部连接文件 |
| `skills_dir` | `./skills`，本地技能资料和静态资源根目录 |
| `data_dir` | `./data`，运行数据根目录 |
| `capability_discovery_timeout_seconds` | `120` 秒，启动、手动刷新、规划及运行准备每次完整目录发现的独立时限 |
| `planning.model_call_max_attempts` | `3`，每轮规划模型传输的最多尝试次数，包含首次 |
| `planning.model_response_max_attempts` | `3`，规划连续无效响应及工具错误的纠错额度，成功读取后清零 |
| `planning.tool_call_timeout_seconds` | `120` 秒，每次规划资源工具或最终提交工具交互的超时 |
| `planning.max_cycles` | `20`，每次规划的决策轮次上限，包含资源读取与最终提交 |
| `execution.model_call_max_attempts` | `3`，每轮模型传输的最多尝试次数，包含首次 |
| `execution.model_response_max_attempts` | `3`，连续无效响应、工具参数或业务错误及工具超时共用的尝试额度，成功调用后清零 |
| `execution.tool_call_timeout_seconds` | `120` 秒，每次执行工具交互的超时，不包含目录发现、运行记录创建或图片保存 |
| `execution.image_history_rounds` | `3`，执行上下文保留原图的最近有图片决策轮数，同轮多图全部保留 |
| `execution.goal_max_failures` | `10`，同一运行中每个 Goal 独立累计的失败次数上限 |
| `execution.max_cycles_by_task_type.act` | `30`，每次 Act 的决策轮次上限 |
| `execution.max_cycles_by_task_type.judge` | `10`，每次 Judge 的决策轮次上限 |
| `execution.max_cycles_by_task_type.goal` | `10`，每次 Goal 的决策轮次上限 |
| `cors_origins` | `["http://localhost:5173"]`，允许的浏览器来源数组 |
| `debug` | `false`，应用调试设置 |

规划及各类执行任务的轮次上限范围为 1～100，模型传输尝试及连续纠错次数范围为 1～10，Goal 累计失败上限和图片保留轮数必须为正整数，工具与发现超时必须大于零。

规划控制参数仅由应用计数，不加入模型上下文。传输重试不重复计轮，工具超时不自动重放；最后一轮合法 `finish_plan` 可完成规划。完整用例、参考计划、本轮输入及成功加载的 Skill 保留在必要上下文中，容量不足时明确失败并保留已有计划。实际配置须包含独立的 `[planning]` 段和根级发现超时字段。

每次任务执行独立计算轮次；完整执行参数随运行固定并保存。Goal 失败次数在同一运行内按 Goal 累计，通过不清零；上限来自本次运行快照。图片窗口只影响模型上下文，历史原图继续保留，后续可在同一运行内按图片标识重读。

需要改变浏览器请求的后端地址时，按 [frontend/.env.example](frontend/.env.example)配置 `VITE_API_ORIGIN`，填写不含 `/api` 的后端 Origin。默认留空，使用前端同源请求及本地开发代理；修改后重启前端，构建产物需重新构建。

## 历史与报告

“历史记录”支持按用例、关键字、创建日期和结果筛选，默认查看最近 30 个上海自然日。列表和统计使用相同基础筛选范围，点击结果标签进一步筛选列表；关闭详情后保留原筛选和页码。

报告保留运行所绑定计划的原始用例、全部实际任务执行、观察、判断说明和运行环境。列表展示当前用例名称，报告中的原始用例来自当次计划，因此编辑用例后两者可能不同。Goal 回跳产生的多次执行均可追溯。

运行结束后可下载：

- **JSON**：完整结构化报告、事件历史与附件清单。
- **HTML**：可离线查看的报告，包含已保存图片。

每次导出产生独立文件，不覆盖之前的导出。重新执行会返回该用例的最新计划确认页，再创建新运行。

默认本地数据如下；改变数据根目录后，这些默认位置随之变化：

| 位置 | 内容 |
|---|---|
| `data/app.db` | 用例、计划、运行、事件和附件记录 |
| `data/checkpoints.db` | 执行图保存记录 |
| `data/artifacts/` | 原始图片和生成的导出文件 |

可在应用配置根字段中填写可选的 `database_url` 与 `checkpoint_path`，分别指定数据库连接和执行图保存位置；省略时从 `data_dir` 推导。应用不会主动删除历史数据；备份应在停止应用后同时保留数据库、执行图保存文件和附件。

密钥、设备配置、运行数据和诊断记录保留在本地，不提交到源代码仓库。运行内容会按任务需要发送给配置的模型服务。当前开发阶段的数据格式可能随版本变化，升级时不提供旧运行数据和快照的兼容保证。
